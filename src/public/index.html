DevPilot MCP: give your coding agent the issue, the code, and the failing tests in one loop.

A Model Context Protocol server that hands AI coding agents like Claude Code structured, size-capped context: GitHub issues, ripgrep search, project docs, and test runs with failures grouped by root cause. It makes no LLM calls of its own. The agent's model does the reasoning.

6 toolsstdio + Streamable HTTPTypeScript · MCP SDK v2vitest · jest · pytestread-only GitHub

The loop, as six tools

Each tool validates input with zod, returns structured output plus a short summary, and caps its size.

get_issue 1

Fetch an issue with its discussion, labels and linked PRs. Cached for 60 s to save rate limit.

analyze_issue 2

Deterministic extraction: type guess, error messages, stack frames, paths, code blocks, search queries.

search_codebase 3

ripgrep with context lines. Respects .gitignore and skips deps, builds, lockfiles and binaries.

get_docs ·

README, CONTRIBUTING and docs/**, split by heading and ranked by keyword hits for a topic.

run_tests 4

Auto-detects vitest, jest, pytest or npm test. No shell, a timeout, a tree kill, and a sanitized env.

summarize_test_failures 5

Failures grouped by normalized error, largest first, with the likely source files to fix.

Connect

Add DevPilot to Claude Code, or to any MCP client.

Local (stdio, works on the repo in your current directory)
claude mcp add devpilot -- npx -y @ashbruh22/devpilot-mcp
Remote (Streamable HTTP, works on this server's demo repo)
claude mcp add --transport http devpilot https://devpilot-mcp.onrender.com/mcp
Then ask Claude Code
Use devpilot to run the tests, summarize the failures, and propose a fix for the largest group.

Architecture

Two transports, one core. Tool logic knows nothing about how it is being called.

Security model

Running tests on a public server is remote code execution by design, so it is locked down.

Allowlist only

Only repos in ALLOWED_REPOS, shallow-cloned at boot. Everything else is rejected.

Fixed commands

Test commands come from server config, never from tool input. Filters are validated, and a filter can't pass flags.

Resource limits

Timeout with process-tree kill, capped output, one concurrent run per repo, and a per-IP rate limit.

Least privilege

Non-root container, a read-only fine-grained token, and secrets stripped from child processes.

Path guard

Every path is resolved and checked against the workspace root. Symlink escapes are rejected.

No arbitrary fetches

Tools never fetch URLs from their inputs. GitHub is the only outbound API.

Why no LLM inside?

Deterministic

The same issue yields the same extraction, which you can test with fixtures.

Cheap and fast

There are no tokens spent server-side and no second model in the loop.

The client already reasons

The server's job is to return clean, compact context, and the agent decides what to do with it.
